Kernel baseline `Drzet/linux@a5ebb76233b79db01e82e061173cb73c6d2b5c6b`. Device observed by prior read-only ADB: Motorola `XT2251-1`, PVT, hwrev `0xC000`, SKU `dn`, Android 14 `U2SLS34.1-42-14-11`.

### SGM41516D: physical model and ID ambiguity

The pinned `sgm4154x_charger_lite.h` says `SGM4154x_PN_MASK=GENMASK(6,3)`, `SGM4154x_PN_41542_ID=BIT(6)|BIT(5)|BIT(3)`, and **`SGM4154x_PN_41516D_ID` has exactly the same value** `0x68`. The lite driver at lines 2267–2282 reads `REG 0x0b` and its probe at 3367–3369 compares to **SGM41542_ID**, not a uniquely identifiable 41516D ID. The code's own `of_match_table` includes `sgm,sgm41516D` at lines 3537–3542.

**Result:** a matching `0x68` part number cannot distinguish those two chip labels in the checked driver. Whether their silicon behavior is truly compatible in all charge/OTG modes is **unproven**. Do not add an oneli `sgm41516D` → `sgm41542` DT compatible alias or remove chip checks. Start by confirming a **SGM41516D datasheet/device revision** or exact oneli source, and audit hardware operation before touching a charger enable.

The apparent stock manufacturer conflict has a concrete likely source explanation: `sgm4154x_charger_lite.h` line 12 literally defines `SGM4154x_MANUFACTURER "Texas Instruments"`, and `sgm4154x_charger_lite.c` lines 1221–1226 reports that macro through `POWER_SUPPLY_PROP_MANUFACTURER`, while `MODEL_NAME` is the name selected by the vendor 41516D build. **[INFERRED]** This explains the observed stock string combination; it does not prove this comparator's exact revision is present on the live Android phone. The baseline upstream driver's manufacturer is separately `"SGMICRO"`.

### Register and conversion evidence (source, not validation of oneli silicon)

| Functional area | Motorola-derived driver source | Mainline comparison / required work |
| --- | --- | --- |
| ID and reset | I2C read `0x0b`, PN mask bits 6:3; 41516D and 41542 both expect `0x68` | Mainline reads same register and mask; no unique 41516D ID, no alias without explicit chip/source review |
| I2C input current | `0x00` bits 4:0, 100000 µA minimum + 100000 µA per code, up to 3800000 µA | Same base representation. Source initial oneli limit 1200000 µA |
| Charge enable/OTG | `0x01` bit 4 CHG_EN, bit 5 OTG_EN, bit 6 watchdog reset | Hardware CE pin is **separate**: PM8350C GPIO2 active-low in oneli. Need ownership and fail-safe startup sequencing |
| Fast charge current | `0x02` bits 5:0, **60000 µA** per step, 0–3780000 µA source range | Oneli `ichg=700000`, `ichg-max=1200000` µA; rounding/clamping and actual programmed value need review |
| Precharge + termination | `0x03` high/low nibble, 60000 µA step plus 60000 µA baseline | Oneli `iprechg=180000`, `iterm=200000` µA; quantization prevents assuming the literal 200000 is programmed exactly |
| VREG + fine adjustment | `0x04` bits 7:3, 3856000 µV base + **32000 µV** steps; `0x0f` fine trim 0/+8/-8/-16 mV | Oneli normal 4400000, max 4600000 µV; handling trim and conversion must be chip-reviewed |
| Charging / fault monitoring | `0x08` charge status/PG/VBUS; `0x09` fault / TS | Mainline core reporting is analogous; no guarantee safety/thermal integration with Motorola policy |
| Reset/watchdog/JEITA | Vendor driver config from `init-charger-disabled`, term/precharge, watchdog and JEITA DT | Direct policy must be reviewed; avoid globally enabling charging while aggregation/load switches unported |
| IRQ/supply/side GPIOs | Vendor oneli TLMM51, PM8350 S10B vdd-i2c, GPIO2 charge-enable, PM8350B GPIO1/3 low/high load | Mainline `sgm41542` does not own Motorola paired GPIO load policy |

The upstream presence of a common SGM register map is **not** enough to declare complete 41516D compatibility. The current PIN/ID conditions and disabled-state requirements are more consequential than the nominal register overlap.

## 2. Motorola power policy is not part of an SGM register driver

The reviewed SM8250-source `mmi_charger` uses `mmi_register_charger_driver` callbacks to combine multiple `mmi_battery_pack` structures. The source-level policy **requires both main GLINK and flip SGM/BQ paths**. The oneli stock ADB confirms exactly such registered categories (`main_battery`, `flip_battery`, `mmi_battery`, `charger`) but does not prove this comparator's implementation was built.

| Oneli DT field | Motorla-derived source consumer and meaning | Mainline gap |
| --- | --- | --- |
| `mmi,paired-id=<1>` for flip, `<0x10000>` for main | `mmi_update_paired_battery` matches reciprocal high/low 16-bit IDs at lines 1379–1410 | No upstream paired pack registry or cross-notify |
| `mmi,paired-ichg-table=<60 1200 90 900 120 600 150 300>` | `sgm4154x_paired_battery_notify` computes ESR-adjusted **open-circuit voltage delta** (mV) then picks a charge-current cap from table (mA), lines 2794–2815. This is NOT an ordinary `delta_soc` charge table even though delta_soc is also logged | Cannot copy table into SGM current driver as unconditional values |
| `mmi,paired-load-thres=<800 400>` | OCV-delta-guided OFF/LOW/HIGH load state plus protective overrides; GPIO1/3 are asserted in `sgm4154x_charger_config_charge` lines 2388–2460 | Battery-to-battery load path / protection absent in mainline |
| `mmi,mmi-temp-zones` six quadruples | Aggregator parses as `temp_c, norm_mv, fcc_max_ma, fcc_norm_ma`, selects zones and currents, controls charger config | Not identical to kernel `thermal-zones` trip table; not portable by simply copying thresholds |
| `mmi,upper-limit-capacity=<80>`, common `lower-limit-capacity=<65>` | Aggregator's charge upper/lower limits are applied in `mmi_update_charger_status` **only if `enable_charging_limit && factory_version`**, source lines 1485–1498 | Oneli source values are **not proof** that ordinary consumer charging stops at 80% |
| `mmi,combo-batt-psy` | Vendor GLINK supplies may delegate combined capacity/current; aggregator publishes named `mmi_battery` power_supply | Mainline `qcom_battmgr` does not implement combined oneli pack policy |

The exact Motorola-derived `mmi_combine_battery_soc` weights SoC by each pack's **full capacity** `sum(soc*full_uah)/sum(full_uah)` (lines 1830–1848); `mmi_combine_battery_current` adds pack currents, charge counters add, voltage is arithmetic mean and combined temperature chooses hottest present pack (lines 1901–1960 and 2113–2129). The `mmi_battery` power supply is exposed as `TYPE=MAINS` by this comparator's `mmi_psy_desc` lines 2740–2747, explaining why physical battery labels can have unconventional types. These are **source algorithms**, not proof of exact oneli installed code/aggregation or voltage/power-path wiring.

The BQ27426 Motorola-derived `bq27426_fg_mmi.c` **resolves the previously unknown `mmi,temp-source=1` value**: enum lines 205–209 establishes **`TEMP_SOURCE_EXTERNAL=1`**; at lines 2142–2173 it selects that value in the gauge `OpConfig` class-64 block, and lines 2387–2395 also read `mmi,ibat-invert-polority`, changing current sign. The exact oneli DT includes `mmi,batt-profile-name="NM40_ATL_712MAH"`, which the comparator has a conditional matching profile definition (lines 74–75 and 229), but **whether the exact oneli board's data-flash profile and temperature source are configured this way under mainline is untested**. Upstream bq27xxx matching `ti,bq27426` is not equivalent to executing this Motorola profile/polarity logic.

### Recommended division of labour / patch roadmap

1. **Independent SGM core driver extension candidate:** compare 41516D datasheet and exact hardware-register feature set with upstream `sgm41542_charger.c`; if evidence justifies, add a **new explicit** `sgmicro,sgm41516d` match only after documented ID ambiguity, range/FT tests and error unwinds. Handle passive read-only probe and unknown chip revision safely; **no enabled oneli DT** at this stage. Alternatively a separate 41516D-specific driver and binding if differences are material. Driver I²C setting alone does not make charging safe.
2. **Separate Motorola paired-battery manager:** implement main/flip aggregation and communication with GLINK, BQ27426 and charger through standard power_supply interfaces, required present/age/OCV checks, ESR/delta OCV and protective GPIO state machine; validate as a source-derived state machine with synthetic tests. Do **not** import an entire Android tree or publish proprietary policy without review.
3. **Gauge adaptation:** evaluate documented BQ27426 fuel-gauge profile calibration and OpConfig external temperature/polarity behaviour against upstream bq27xxx with **no assumption that a missing property is harmless**.
4. **Only after explicit policy and hardware tests:** enable TLMM51 IRQ, low/high load PMIC GPIO controls, regulator S10B and PM8350C CE active-low, charger GPIO safety, current/voltage charging, thermal mitigation. Stock ADB observed flip charging, but mainline charge controls were never exercised.
5. **GLINK source and signed temperature fix:** existing standalone patch [kernel PR #4](https://github.com/Drzet/linux/pull/4) is independent of all battery/chip work. A zero-copy KUnit test and ARM64 object compile passed for the byte-identical source in the original branch, but the new standalone head has not itself been rebuilt.

**Exact oneli driver provenance still missing:** no Linux image/modules from the physical Android 14 oneli firmware has been disassembled for this charger stack. Pinning SM8250/Lineage comparator files is adequate for a concrete plan, not for claiming that their register writes and Qualcomm/Motorola policies match byte-for-byte the device. This is an explicit, bounded source gap.

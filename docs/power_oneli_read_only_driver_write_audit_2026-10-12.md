## Exact GLINK probe, notification, read, write and error paths

Inspected **actual standalone Power fix tree** `qcom_battmgr.c`:

1. **Probe** `qcom_battmgr_probe` (1628–1729): selects parent OF variant or fallback `QCOM_BATTMGR_SM8350`; runs `qcom_battmgr_charge_control_thresholds_init` (733–759), whose `nvmem_cell_read_u8` calls read charger-limit state from NVMEM, not an active firmware write. Registers SM8350 battery/USB/WLS power supplies (1693–1713), allocates callback client, calls `pmic_glink_client_register` (1727). Registration and firmware service notifications are **not no-I/O**.
2. **Service-up / initialization** (1588–1611): `qcom_battmgr_pdr_notify` schedules `enable_work` on service-up and `qcom_battmgr_enable_worker` calls `pmic_glink_send` with `BATTMGR_REQUEST_NOTIFICATION=0x04` (GLINK header `PMIC_GLINK_NOTIFY`). This is an **outbound protocol message** even with no sysfs writes; it requests notifications but is not, by its defined opcode, a direct charging-current/enable command. Native firmware ACK/layout still untested.
3. **Power supply reads:** `qcom_battmgr_bat_get_property` calls `qcom_battmgr_bat_sm8350_update` to send `BATTMGR_BAT_PROPERTY_GET=0x30` with `battery=0` and property ID. Includes voltage, current, SOC, temp, cycles and health (SM8350 properties lines 868–898). `BATT_TEMP=12` is interpreted signed by `qcom_battmgr_decode_temperature` in the standalone patch at callback lines 1439–1442; existing host ARM64-object and real UML KUnit 3/3 evidence stands. USB and WLS getters send their `GET=0x32/0x34` messages; status notification opcode `0x07` only calls `power_supply_changed` for events. Getters do not by themselves prove installed oneli firmware responds correctly.
4. **Write-capable path present in common code:** `qcom_battmgr_set_charge_control` (664–676) **sends opcode `BATTMGR_CHG_CTRL_LIMIT_EN=0x48`, `enable=1`**, with target and delta SOC. Both charge-threshold set paths call it (679–730); set-property dispatch at 776–795. **Important variant distinction:** `sm8350_bat_psy_desc` lines 892–898 has ONLY `get_property`, **no `set_property` or `property_is_writeable`**, so default oneli-fallback SM8350 branch does *not* expose this charge-threshold write route. `sm8550_bat_psy_desc` lines 926–934 **does**. Do not describe the whole driver as globally read-only, nor claim the SM8350 branch emits `0x48` on probe.
5. **Errors/retries:** common `qcom_battmgr_request` (346–364) calls `pmic_glink_send`, waits **HZ** for completion and returns `-ETIMEDOUT` when absent. Power supply getters check `service_up` and return `-EAGAIN` when down. No battery property success or decoded thermal reading is claimed on actual oneli. No changes to GLINK handshake made here.

**Safe proposed GLINK gate:** use only default SM8350 GET + notification request with no threshold writable operations; keep oneli GLINK board service disabled in the *minimal kernel* until Boot/Power agree source/firmware semantics and independent host fault tests for GET/ACK, wrong payload length, stale values, service loss and client lifetime. Report temperature as a battery property, **not** a substitute for validated thermal-zone/charging cutoffs.

## Exact BQ27426 *writes* (why current drivers are not read-only)

**Mainline existing BQ27426** I²C driver (baseline):
- Probe `bq27xxx_battery_i2c_probe` (156–214) assigns **both** `di->bus.write` and `di->bus.write_bulk` (186–189), then `bq27xxx_battery_setup`, initial reading and periodic poll (setup lines 2227–2270; core update 1915–1966), plus an IRQ handler. Simply exporting read-only power-supply attributes does **not** remove I²C write capability.
- Core `bq27xxx_battery_settings` (1516–1566) calls `power_supply_get_battery_info`; if a battery-info object supplies (a) **both** design energy and capacity, or (b) design-minimum voltage, then it invokes `bq27xxx_battery_set_config` (1471–1514). That calls **unseal**, reads/updates data memory and can write block/checksum, perform `SET_CFGUPDATE`/`SOFT_RESET`, then **seal** (1312–1469). Even if a new PVT board node uses the correct `ti,bq27426`, **do not add a `monitored-battery` / battery-info supply silently**. The downstream `design-capacity=712` and `mmi,batt-profile-name` are not proof mainline parsed this same battery-info interface. With absent battery-info, that *specific* configuration routine returns without writes; this does **not** constitute an enforced read-only I²C transport.
- Read/poll code handles standard `FLAGS`/`SOC`/voltage/current and other registers. Oneli current-polarity and external-temp settings must be reconciled before presenting measurements as correctly scaled.

**Motorola-derived family BQ27426**, not exact oneli implementation:
- Probe (2441–2564): enables `vdd-i2c`, executes `fg_read_fw_version` (1005–1025), which **writes the FW-version subcommand** to control register before reading. Requests IRQ, explicitly invokes IRQ thread, starts heartbeat after 1 s.
- `determine_initial_status` (2346–2355) from heartbeat **unconditionally calls `fg_update_bqfs` and `fg_select_external_temp`** on first initialization. `fg_update_bqfs` (1747–1816) checks for ITPOR/chem/DM-version, and if update required enters data-memory access and executes `CMD_W` blocks through `fg_update_bqfs_execute_cmd` (1699–1745), potentially writing the battery profile. `fg_select_external_temp` (2143–2173) enters config mode, writes `DM class64/OpConfig` and exits/reset/seal **even if temp-source equals the existing value**. This alone disqualifies wholesale adoption as an enforcement of read-only reporting.
- Other writes: `fg_check_init_completed` and `fg_get_seal_state` issue control *subcommands* (595–647); `fg_dm_read_block` writes address-selector registers before reading (914–949); update/debug sysfs can request profile rewrite or full gauge reset (1969–2008), and `fg_change_chem_id` can issue chem-id and control operations (1600–1667). Not all commands are equally state-changing, **but none is literally bus-read-only**. Probe/error cleanup also enables and later disables S10B I²C regulator supply, a separate power-state change.

**Conclusion:** no unmodified Motorola-family BQ driver, and no falsely labelled mainline gauge with unrestricted write bus, may enter the *read-only native profile*. A reviewable optional reporting module could instead use **verified, register-only BQ27426 measurements without control-subcommands**, backed by injected-I²C-write-denial tests covering probe, poll, IRQ, suspend/resume and all error paths. Do not claim that a host no-write test alone proves electrical behavior. Keep gauge node disabled until such a contract is implemented and reviewed.

## Proposed bounded acceptance and future tests

1. **Power source:** canonical [supply audit](power_oneli_pvt_usb_supply_audit_2026-10-12.md) now includes VPU's exact one-Boolean PVT fragment48 correction. No additional PVT voltage overrides found in fragment48, no source support for PMIC input-parent HDK transplant, no kernel supply patch approved.
2. **Read-only profile candidate:** battery/USB/WLS reports over default SM8350 GLINK GET paths if service behavior is verified; BQ27426 at I²C 0x55 via strictly allowlisted measurement reads *only after* no-write host policy tests and current/temperature agreement. Label GLINK request-notification `0x04` as an outbound write *message* even though it is notification registration, not physical charge control. Reject any charging or thermostat actuation path, any `BATTMGR_CHG_CTRL_LIMIT_EN=0x48`, BQ DM/NVM writes, charger I²C `0x6b` and load GPIO writes in reporting profile.
3. **Minimal disabled build:** do not enable the PMIC-GLINK, BQ27426, SGM41516D, paired battery aggregation, RPMh supply nodes or thermal charging consumers merely to make an Image/modules pass. Stage next diagnostics without depending on active power policy.
4. **When combined artifact exists:** integration kernel `razr/integration-candidate@2b5acf108ae37040ac1e652e029bb37f5609e886` currently includes exact same 5 source blobs as isolated Power `564f2c7d...` (compared file blob SHA **5/5 match**); its recent CI workflow commit adds builder, not proof of completed modpost/run or native operation. 5. **Physical gate:** stock SGM41516D identity and paired safety policy, real current sign/temperature units and firmware GLINK replies require phone or attributable stronger source. No active charger or USB/DP rail enablement follows from this analysis.

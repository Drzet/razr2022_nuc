### Output, arithmetic and lifecycle contract

1. **Per session, before route clamp:** calculate independent `calc_bw_ddr=D` and `calc_bw_llcc=L`. Internals are fixed-point **MB/s** with decimal units: bitstream Mbit/s terms divide by 8, pixel/collocated/line-byte terms divide by 1,000,000. `kbps(fp_round(total))` multiplies rounded MB/s by **1000**, yielding **kB/s**, not bits/s or KiB/s. Output steps are 1000 kB/s. Read both output fields; a zero function return is not zero bandwidth.
2. **Cache accounting:** cache-on divides DPB DDR reads by 1.30 (H264 category) or 1.14 (HEVC/VP9); H264-category top-line reads/writes move into LLCC. DDR total then receives factor 1.03. LLCC total is **that DDR total plus cache DPB/top-line traffic**, not an extra delta to add to DDR. With cache-off those extra terms vanish, hence L=D. Both totals receive 25% extra at fps ≥960; K's 480 fps limit excludes that branch from a claimed supported candidate workload.
3. **Rounding/bounds are part of reuse:** V Q16 fractions are truncated to hundredths before conversion; `fixedpoint.h` uses `size_t` with one-quarter of word bits fractional (16 on ARM64). `fp_mult`/`fp_div` truncate intermediates; `fp_round` rounds up when fraction ≥`65535/2` (32767), not an exact mathematical half threshold of 32768. Preserve this if claiming extracted-reference equivalence. V `vidc_bus_vote_data.bitrate` and local `width,height,fps` are signed `int`; dimension/rate/byte products can overflow before conversion. For example 3840×2160×480 exceeds `INT_MAX`; this is an arithmetic example, **not** an admitted K workload or an executed test. A later adapter must validate admission and all positive denominators, check/widen products, and bound each fixed-point multiply/shift before accepting outputs. Saturating the final ICC request cannot repair earlier overflow. No safe complete input envelope or overflow-test success is asserted here.
4. **Aggregate then clamp:** V `msm_vidc_set_buses` sums D and L separately over sessions with input and recent activity, using `u64`; turbo sets both to `INT_MAX`. Its NRT override uses platform `bus_bw_nrt[0]` and debug overrides can replace totals. These are outside the selected RT decoder calculation; do not import them as new SM8475 defaults. Clamp each **summed** data request independently to its route's [1000,15000000] kB/s range from the accepted stock export; CNOC is 1000. Do not clamp per session or sum L with D. V suppresses changes <50000 kB/s when a previous nonzero vote exists; this optimization is separate from calculated demand and may leave an older applied vote.
5. **Peak/unvote:** V Iris2 `__vote_buses` passes peak **0**, not `2*average` (AR50LT only). A normal sum of zero still clamps to the active minimum; it is not unvote. `__unvote_buses` requests `(0,0)` for every path and clears cached totals, but exits on an ICC error, so source alone does not guarantee all hardware votes clear. A future consumer must propagate errors and clear both data paths plus CNOC during successful suspend/unwind; retry/rollback on partial updates needs explicit tests. K's current helper accepts only one D and cannot consume this pair. Reuse the already accepted disjoint routes; do not reopen topology or add a full L on a long D path.

### Specific stop, implementable alternative and proposed patch boundary

**HOLD cache-aware production input:** source-defined CR/CF fallback and available DPB/rate fields close most inputs, but K supplies no truthful runtime `use_sys_cache` value. V `venus_hfi.c::__enable_subcaches` calls `llcc_slice_activate`; `__set_subcaches` submits active slice IDs/sizes using `HFI_BUFFER_SUBCACHE` and sets `sys_cache_res_set` only after command-queue write. Release/deactivation clear resources. That flag describes host lifecycle/submission, not proof of firmware acceptance. An equivalent K state must be defined with activation/submission/failure/release semantics before selecting the discounted branch; neither stock slice names nor an invented Boolean suffices. This is a source/interface hold, not a request to redo firmware extraction or wait for hardware to perform source analysis.

**Implementable alternative for coordinator selection:** define an explicit **no-cache-discount reference policy**, using the vendor cache-off branch as a model regardless of actual cache state, with CR=1 and CF=4 source fallbacks; begin with linear NV12/P010 H264/HEVC/VP9 and positive, admitted, overflow-checked dimensions/rates/queued bytes. This deliberately produces D=L and makes no claim that physical cache is disabled or that votes are calibrated. It avoids inventing runtime cache activation, but still needs coordinator agreement on rate startup/limits and checked arithmetic; it is **proposed, not implemented or accepted**. Alternatively assign the narrow K cache-lifecycle/input contract above before a cache-aware reference. Compressed capture can follow only with the K split-mode adapter, never V's unified shortcut.

### Interconnect: endpoint and aggregation contract

Stock `/soc/qcom,vidc@aa00000` has `interconnects=<75 2 164 555>, <72 3 72 512>, <828 36 75 565>`. Resolve phandles through the committed JSON and symbols through V [`qcom,waipio.h`](https://github.com/LowTension/android_kernel_xiaomi_sm8475/blob/39382bf760ccf05a8fb4dddee7138ecac02d4a59/include/dt-bindings/interconnect/qcom,waipio.h) and [`waipio.c`](https://github.com/LowTension/android_kernel_xiaomi_sm8475/blob/39382bf760ccf05a8fb4dddee7138ecac02d4a59/drivers/interconnect/qcom/waipio.c). Mainline pairs use K [`qcom,sm8450.h`](https://github.com/Drzet/linux/blob/a1f0288d7c3d8d51fc53398d0ffe6bcdff8a54ac/include/dt-bindings/interconnect/qcom,sm8450.h), **with a tag cell on each endpoint** (`#interconnect-cells=2` in `sm8450.dtsi`):

| Stock path; resolved provider/endpoint | Mainline provider/endpoint symbols | Source route / intended request |
| --- | --- | --- |
| `venus-cnoc`: GEM 75:2 → CONFIG 164:555 | `gem_noc MASTER_APPSS_PROC` → `config_noc SLAVE_VENUS_CFG` | `chm_apps → qns_gem_noc_cnoc → qnm_gemnoc_cnoc → qhs_venus_cfg`; `cpu-cfg`, average 1000 kB/s |
| `venus-ddr`: MC 72:3 → MC 72:512 | `mc_virt MASTER_LLCC` → `mc_virt SLAVE_EBI1` | `llcc_mc → ebi`; DDR average D |
| `venus-llcc`: MMSS 828:36 → GEM 75:565 | `mmss_noc MASTER_VIDEO` → `gem_noc SLAVE_LLCC` | `qnm_video → qns_mem_noc_sf → qnm_mnoc_sf → qns_llcc`; LLCC average L |

K [`sm8450.c`](https://github.com/Drzet/linux/blob/a1f0288d7c3d8d51fc53398d0ffe6bcdff8a54ac/drivers/interconnect/qcom/sm8450.c) contains those links, **plus `qns_llcc → llcc_mc → ebi`**. Consequently a single `mmss_noc MASTER_VIDEO` → `mc_virt SLAVE_EBI1` `video-mem` request already covers LLCC and DDR. It reaches LLCC's `bcm_sh0` and DDR's `bcm_mc0`/`bcm_acv`; no separate LLCC vote is needed merely to reach those providers. These BCMs have different policies (`SH0`/`MC0` keepalive, `ACV` enable mask); graph coverage is not measured bandwidth. K [`icc-rpmh.c::qcom_icc_aggregate`](https://github.com/Drzet/linux/blob/a1f0288d7c3d8d51fc53398d0ffe6bcdff8a54ac/drivers/interconnect/qcom/icc-rpmh.c) **sums averages, takes maximum peaks**, per tag bucket; zero tag defaults to `QCOM_ICC_TAG_ALWAYS`. Adding a full LLCC average L on top of that long DDR request D would sum **D+L** on the shared video→LLCC nodes. That double-counts the DDR contribution already included in L.

V [`msm_vidc_power.c`](https://github.com/LowTension/android_kernel_xiaomi_sm8475/blob/39382bf760ccf05a8fb4dddee7138ecac02d4a59/techpack/video/driver/vidc/src/msm_vidc_power.c), `msm_vidc_scale_buses`/`msm_vidc_set_buses`, feeds `calc_bw_ddr` and `calc_bw_llcc` separately, sums active sessions separately (turbo requests `INT_MAX`), and calls `venus_hfi_scale_buses(D,L)`. V [`venus_hfi.c::__vote_buses`](https://github.com/LowTension/android_kernel_xiaomi_sm8475/blob/39382bf760ccf05a8fb4dddee7138ecac02d4a59/techpack/video/driver/vidc/src/venus_hfi.c) clamps each request to its DT range; CNOC uses its maximum. It calls `icc_set_bw(path, average, peak)` in **kB/s**. For this comparator's `VPU_VERSION_IRIS2` the peak is **zero**; `2*average` is only the AR50LT exception. `__unvote_buses` clears all paths. `__init_bus` may skip LLCC when the explicit syscache-disable switch is set; that switch's value on the phone is not established.

V [`msm_vidc_power_iris2.c`](https://github.com/LowTension/android_kernel_xiaomi_sm8475/blob/39382bf760ccf05a8fb4dddee7138ecac02d4a59/techpack/video/driver/variant/iris2/src/msm_vidc_power_iris2.c), `msm_vidc_calc_bw_iris2` and its decode/encode calculations, supplies the reason for separate votes: decode `llc.total = llc.dpb_read + llc.line_buffer_read + llc.line_buffer_write + ddr.total`; encode likewise adds cache traffic to DDR. `use_sys_cache` is set from `core->dt->sys_cache_res_set` in `msm_vidc_scale_buses`. Thus **L includes D, rather than being an extra delta**. With cache traffic absent the formula gives L=D; cache traffic can make L>D. Stock's `cache-slice-names="vidsc0"` alone does not establish runtime cache activation, savings or a calibrated workload request.

**Decision:** a two-path CNOC + long video→DDR arrangement suffices for topology and a deliberately equal D=L contract. It is not evidence of vendor-policy equivalence for cache-enabled workloads. To preserve independently computed D and L, use the **two non-overlapping data routes in the table**, plus CNOC; do not append a third full vote to the existing long path. A residual `L-D` overlap scheme would require additional assumptions and is not selected. The source case for a separate dynamic LLCC request is its independent cache-inclusive average, not the number of stock paths.

## Executed regressions and correction

[Failing-before logs/results](../../tests/results/2026-10-14-usb-ptn3222-offline/lifecycle/before/lifecycle-result.json) execute actual production generic PHY dispatch/count bodies plus actual common SNPS/PTN3222 bodies from d513929, under explicitly scoped mocks. This closes the prior gap where direct provider exit was incorrectly treated as consumer-reachable failed-init recovery.

| Case through actual core/SNPS dispatch | Before d513929 | Corrected behavior |
| --- | --- | --- |
| Init/tuning `-EIO` with transient cleanup failure, then normal core init retry | Counts 0/0 and both votes retained; retry `-EBUSY` never reaches cleanup. | First `-EIO` is preserved. Provider init retries pending cleanup before new votes. Successful retry reaches counts 1/1 with reset released; no unbind/direct provider exit required. |
| Successful init → provider exit cleanup failure → consumer reconnect | Outer exit returns 0, inner count remains 1, reset asserted. Reconnect falsely succeeds with counts 1/2 and faulted provider. | SNPS retains its outstanding repeater reference and drains pending exit before new power/init. Reconnect genuinely initializes with counts 1/1, one vote per rail and reset released. |
| Cleanup remains failed | Repeated failed-init retry is permanently blocked; reconnect can skip provider init. | Retry returns actual cleanup `-EAGAIN`, retains fault/reset/vote state and outer count 0; no successful consumer init or duplicate votes until cleanup succeeds. |

**Provider:** PTN3222's faulted init path now retries recorded power cleanup and clears fault only on success, preserving the existing tracked voltage/enable state. No change to profile tuning, identity policy, power ordering, successful role replay or profile-absent legacy behavior.

**Consumer:** SNPS records ownership of its successful repeater init reference, retains it on failed exit or later-init unwind, and retries exit before reacquiring its resources. Later clock/reset/SoC failures preserve their initiating errors. Completed SNPS own teardown continues to return 0 while logging deferred repeater cleanup: returning a negative outer exit error would retain outer core `init_count=1` and cause the next `phy_init` to bypass SNPS as well. Persistent deferred cleanup errors instead propagate on the next initialization, keeping the outer count at zero. This is deliberate deferred cleanup, not a claim that all electrical power transitions completed.

Generic PHY core and DWC3 are unchanged. The existing core dispatch contract is reused, rather than rewriting reference-count behavior. Core source SHA256 **`2535dc20688c48082b30f2498a05931897dc7b5db902bb02c5f5322d31c80117`** is identical before/after. Retained upstream/vendor/community provenance and exact coverage limits are in the [prior reuse/adaptation handoff](https://github.com/Drzet/razr2022_nuc/blob/2b64829bd78478a89e18d5bd50952f7a72e3f0c5/docs/handoffs/2026-10-13-usb-tenth-round.md): Motorola `0450c5076a8ec9415a10888c8c183ef6ff5f91b8`, existing stock export, upstream PTN3222 and the pinned community regmap/unwind precedent. No new survey/import or ABI redesign was needed for this project-specific defect.

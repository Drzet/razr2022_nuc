## Why the identity policy changed

The reference drawing identifies **U1720 = PTN3222BUK**, sheet68/84 of DZKJ `Schematics_256_MP_0616.pdf`, Motorola **maven.cpm rev03**, 2022. This is auditor/user-transcribed reference-design evidence, not this owner's independent full-PDF inspection or confirmation of the user's installed PVT part. Installed-board correspondence remains **[INFERRED]**. Preserve the independent 2026-10-11 stock ADB/DT evidence; the later failed session does not invalidate it.

Our adaptation had added a strict numeric allowlist that Motorola's implementation does not require. [NXP CUK Rev1.2, 11 August 2023, Table9 p12](https://www.nxp.com/docs/en/data-sheet/PTN3222_CUK.pdf) documents **0x023222**; [HUK Rev2.0, 6 May 2026, Table8 p17](https://www.nxp.com/docs/en/data-sheet/PTN3222HUK.pdf) documents **0x013222**. Neither establishes BUK's ID. The exact source-only findings and bounded BUK search remain in the [previous handoff at5a9e2c5](https://github.com/Drzet/razr2022_nuc/blob/5a9e2c5f4fa743fd79580eac44ccd00379f0ed17/docs/handoffs/2026-10-13-usb-tenth-round.md). No missing BUK datum has been invented or newly found, and no broad reuse audit was repeated.

**Implemented contract:** for the existing explicitly selected `nxp,usb2-tuning-profile = "motorola,oneli"`, `ptn3222_read_id()` reads revision **0x13** and chip-ID bytes **0x14–0x16** after the existing supply/reset startup sequence. It checks all read return codes and assembles `reg14 | (reg15 << 8) | (reg16 << 16)`. A documented numeric ID retains its debug diagnostic. An unrecognised readable ID emits a warning with raw ID/revision and **continues with the board-selected tuning**. It no longer returns `-ENODEV` solely because the number is absent from the CUK/HUK list. This does not expand any list of claimed supported IDs, identify an unknown chip as BUK or establish a silicon revision from matching bytes.

**Retained failures and boundaries:** failed identity reads still return their actual error, assert reset and enter the existing tracked cleanup/retry path before any tuning write. Tuning-write errors, role rollback, voltage/enable vote accounting and lifecycle recovery remain unchanged. The profile still requires explicit reset and supply providers. Profile-absent legacy operation performs no new ID reads or writes. No generic identity bypass switch, new compatible, vendor framework or arbitrary raw-register DT ABI was added. The binding description was corrected to match the policy; constraints are identical.

**Evidence still useful, no longer an ID-allowlist prerequisite:** an attributable BUK register specification/erratum, or a read-only capture of **0x13/0x14/0x15/0x16**, each with its read status, from 7-bit **0x4f** on an identified stock-powered/reset-released oneli board. Keep board/firmware/bus/state provenance and raw bytes. The capture can inform later identification/errata qualification without holding this candidate behind an unsupported rejection policy. The phone is unavailable; no capture or power/reset experiment was attempted. NXP AN13637 remains a named BUK-specific source lead whose contents were not inspected.

## Reset, supplies and interfaces retained

The fixed schematic records **EUSB_RPTR_RST_N**, direct **PM8350C GPIO7**, active-low at the chip. Pinned [Motorola DT `90fa7be1db5bd47202673d4431408659149a7359`](https://github.com/MotorolaMobilityLLC/kernel-devicetree/blob/90fa7be1db5bd47202673d4431408659149a7359/qcom/cape-moto-common-overlay-base.dtsi#L127) uses active-high flags because [vendor kernel `0450c5076a8ec9415a10888c8c183ef6ff5f91b8`](https://github.com/MotorolaMobilityLLC/kernel-msm/blob/0450c5076a8ec9415a10888c8c183ef6ff5f91b8/drivers/usb/repeater/repeater-i2c-eusb2.c) directly sets the descriptor to `bring_out_of_reset`: true drives physical high/release, false drives low/assert. Its debug assertion words are inverted. Its NXP init reads only revision0x13 and does not check the full ID; the earlier adaptation/source record retains exact blob/hash and consumer call evidence.

For a later Boot-owned board change, the established descriptor proposal remains **`reset-gpios = <&pm8350c_gpios 7 GPIO_ACTIVE_LOW>;`**, using Boot's actual PM8350C controller label. Existing upstream-style calls require **no inversion**:

| Action | Logical value | Physical RST_N with active-low descriptor |
| --- | --- | --- |
| Probe `GPIOD_OUT_HIGH` | 1 | Low / asserted |
| Init after supplies | 0 | High / released |
| Abort or exit before cleanup | 1 | Low / asserted |

Physical **GPIO7** is DT cell **7**, pinctrl name **gpio7**, chip-local offset **6**. Baseline [PMIC GPIO translation](https://github.com/Drzet/linux/blob/a5ebb76233b79db01e82e061173cb73c6d2b5c6b/drivers/pinctrl/qcom/pinctrl-spmi-gpio.c#L794) subtracts the physical offset1 and applies second-cell flags; [logical descriptor semantics](https://github.com/Drzet/linux/blob/a5ebb76233b79db01e82e061173cb73c6d2b5c6b/Documentation/driver-api/gpio/consumer.rst#L261) produce the levels above. Do not substitute DT cell6, a global GPIO number, TLMM7 or PM8350BH. Boot still reviews provider/mux/ownership/pin configuration; installed wiring and electrical timing remain untested. No reset-call or shared-DTS patch was made here.

Reuse the schematic and [stock PVT/DT supply evidence](../usb_stock_pvt_variant_ps5169_2026-10-12.md): **vdd1v8-supply → PM8350 S10B**, **vdd3v3-supply → PM8350 L2B**. Schematic nominal **3.07V**, Motorola nominal **3.072V** (vendor range2.7–3.3V) and candidate request **3.075–3.3V** are distinct statements. L2B constraints/provider rounding still need review before integration; do not silently change that range or claim measured3.3V. S10B remains1.8V; load votes remain32mA for S10B /3.5mA for L2B. Parent/provider reconciliation belongs to Boot/Power.

Existing profile sequence is unchanged: enable **1.8V then L2B**, release reset, wait1000–1500us, read identity, write **0x06=0x40, 0x07=0x22, 0x08=0x64** for device/OTG or **0x08=0x24** for host, wait500–1000us. Teardown asserts reset before reverse cleanup. These are source-implemented timings, not BUK electrical qualification. Generic PHY **#phy-cells=0** and the existing SNPS consumer contract remain intact.

## Changes and provenance

The kernel commit adds `qcom,sm8475-snps-eusb2-phy` to the device-tree binding list allowing a fallback to `qcom,sm8550-snps-eusb2-phy`; source model is [community sm8475.dtsi, bf1d29fced6e156dd6090a9b6600a8c44259c114](https://github.com/sm8450-mainline/linux/blob/bf1d29fced6e156dd6090a9b6600a8c44259c114/arch/arm64/boot/dts/qcom/sm8475.dtsi). Upstream baseline already provides `drivers/phy/phy-snps-eusb2.c` matching the fallback and `drivers/phy/phy-nxp-ptn3222.c` matching **only exact PTN3222**. No kernel driver code has been changed.

Detailed, source-backed results: [USB investigation](../usb_oneli_investigation_2026-10-11.md). Key Motorola sources pinned to device-tree `90fa7be1db5bd47202673d4431408659149a7359`:

- `qcom/cape-usb.dtsi`: DWC3 at `0x0a600000`, eUSB2 at `0x088e3000`, combo PHY at `0x088e8000`.
- `qcom/cape-moto-common-overlay-base.dtsi`: NXP I²C repeater `0x4f`, supplies `S10B`/`L2B`, reset `pm8350c` GPIO7, 3 register override pairs, UCSI connector-USB role graph. Alternative Diodes repeater `0x6c` explicitly disabled.
- `qcom/cape-oneli-common-overlay.dtsi` and `qcom/cape-moto-common-redriver.dtsi`: oneli PS5169 I²C `0x30`, supplies `S10B`/`L8C`, orientation GPIO91 and legacy tuning sequence. 
- Motorola kernel `9511d6b2dc469e5bd836992e3bdd6d19ace112e0` repeater `drivers/usb/repeater/repeater-i2c-eusb2.c`: decodes override pairs as (value,register).
- PS5169 upstream proposal: [v3, August 2026](https://patchew.org/linux/20260810-ps5169-bup-v3-0-a2178b2834d7@proton.me/). This is a proposal, not a committed kernel change or demonstrated oneli support.

[INFERRED] The physical NXP eUSB2 repeater may be PTN3222-family, but Motorola's generic `nxp,eusb2-repeater` compatible does not prove its part number. Mainline's specific `nxp,ptn3222` compatible must not be asserted without identification. GPIO reset polarity requires verification. [INFERRED] USB 2.0 gadget/network is the best first debugging target, prior to SuperSpeed/DP.

## Blockers and next test

1. Identify the oneli-installed NXP repeater (actual chip ID/revision) and physical reset polarity; verify three vendor register tunes, then decide whether the upstream PTN3222 generic PHY is appropriate or requires a new driver/binding. Do not guess the exact IC from I²C address alone.
2. Obtain a Boot `razr/boot` SHA implementing the SM8475 eUSB2 PHY, correct DWC3 `&usb_1` and connector graph, validated PMIC supplies and GPIO7.
3. Run schema validation and kernel DT compilation on recorded SHA/toolchain, saving commands/results.
4. First **device acceptance criterion:** a native-Linux boot with stable USB gadget enumeration and functional USB serial/network for debugging on an external host, with `dmesg`, descriptors, role state and exact image/DTB SHAs recorded.
5. Follow with reversible host-mode high-speed test and both orientations. Defer PS5169 and USB3/DP until this works; validate PS5169 reset/VIO sequencing and its upstream v3 driver/binding separately.
